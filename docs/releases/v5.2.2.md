# AI Sales OS v5.2.2

## WhatsApp 外发消息手机多设备同步修复

- 出站目标在调用 Baileys 前统一转换为无设备段的用户级 JID，例如 `号码:0@s.whatsapp.net` 会转换为 `号码@s.whatsapp.net`。
- LID 映射得到的 PN 地址也会再次规范化，设备号不会继续进入 `deviceSentMessage.destinationJid`。
- 每次发送文字或附件前，Bridge 强制刷新发送者和客户的 WhatsApp 设备清单；Baileys 随后使用同一份最新清单同时生成客户消息和发送者其他设备的消息副本。
- 发送成功响应会记录 `senderDeviceSyncPrepared`、发送者设备数和客户设备数，原有服务端消息 ID 与目标号码校验保持不变。

## 防止静默不同步

- 只有确认至少存在一个可接收消息副本的发送者设备，以及至少一个客户设备后，才执行真实发送。
- 无法取得发送者身份、发送者手机设备或客户设备时，会在客户收到消息之前阻断发送，并给出重新连接或稍后重试提示。
- 客户侧“已送达/已读”回执仍只表示客户设备状态，不再被解释为发送者手机已经同步。
- 不会对之前已经发出的消息执行补发，避免客户重复收到。

## 验证、数据与发布边界

- 新增 PN、LID、`:0` 和其他设备号的用户级 JID 规范化回归。
- 新增发送者设备、客户设备、重复设备去重和 Bridge 协议回归。
- 升级不删除或覆盖 `%LOCALAPPDATA%\WAFlow\waflow.db`、客户、WhatsApp/邮件账号、消息、API、自动化、凭据或知识库数据。
- 本版本仅通过 GitHub Release 发布 Windows 中文安装包与 Velopack 自动更新资产，不覆盖、关闭、重启或安装本机正式程序；macOS 构建继续暂停。
